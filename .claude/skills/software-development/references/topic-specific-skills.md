# Topic-Specific Skills

Select skills by the responsibility a task affects, then acquire their governing material before making a judgment that depends on it. This practice clarifies the existing duty to consult matching topic skills; discovery alone does not supply their rules.

## Select by Responsibility

Repository identity is a clue, not an owner assignment. A component change inside an Expo app and an Expo startup change affect different layers. Baseline and phase duties also apply; selecting a domain owner does not replace them.

Bounded structural discovery locates the affected responsibility using the request, adopted project guidance and available skill descriptions. Inspecting file layout, imports and callers can establish which layer is involved without deciding that layer's technical contract.

**Guidelines:**

- MUST select all matching skills by the responsibilities the requested behavior or changed area affects, including applicable baseline and phase duties, rather than by repository identity, file location or edit size alone.
- MUST NOT settle a domain contract from discovery metadata or familiar code before acquiring its governing material.
- MUST defer detailed project and domain rules to their owning skills instead of restating them here.

## Acquire Before Dependent Judgment

A description tells you when a skill applies, not what it requires. The selected body's routing then identifies applicable references; unrelated references and citations do not become required merely because they are linked.

The sequence is:

1. Identify affected responsibilities through the request, adopted guidance, discovery metadata and bounded structural inspection.
2. Acquire all applicable skill bodies.
3. Follow their routing to acquire the applicable reference material.
4. Make the dependent planning, explanation, implementation, verification or review judgment.

**Guidelines:**

- MUST read the full bodies of all applicable skills, then the complete applicable reference material those bodies route to, before the dependent judgment; discovery descriptions, partial excerpts and a later invocation are not substitutes.
- SHOULD read only references relevant to the affected responsibility, changed files or requested behavior; this selection does not shorten an applicable reference into an excerpt.
- MUST stop the dependent judgment and report the missing material or access when required governing material cannot be acquired, rather than infer its rules.

When confirming the source and content actually loaded, consult the project's skill-management practices where available. Without that optional capability, identify the material read and disclose what cannot be confirmed; do not infer successful acquisition from discovery. Installation, retention and loading diagnostics remain that owner's responsibility, not a second selection policy here.

## Reassess Before Newly Affected Work

The starting set is not a ceiling. A task that begins with component padding can later reach route wiring, introducing a framework responsibility before that work is judged or edited.

**Guidelines:**

- MUST reassess selection when additional responsibilities become affected and acquire their governing material before judgments or edits in that area.
- MUST NOT treat an initial selection or supplied material list as exhaustive after the affected responsibilities change.

When reassessment changes a canonical plan, consult the project's change-loop approval and recovery practices where available. Without that optional capability, preserve any approval and amendment gates the project requires, report unresolved approval before dependent work, and treat execution or review results dependent on a superseded plan as stale until regenerated against the approved amended plan. Acquiring another skill does not authorize a plan change.

## Contrasting Examples

These examples derive selection from current responsibility boundaries, not a fixed installed catalog. They do not replace the selected owners' technical rules or waive baseline, testing and review duties.

Compare the following tasks:

| Task                                                                     | Applicable domain responsibilities                                                                    | What does not decide selection                                                                                      |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Component-owned padding edit                                             | React component development and React component styling                                               | A small edit does not remove component-development duties; an Expo repository does not itself add framework duties. |
| Props and styling change                                                 | React component development and React component styling                                               | Framework references do not apply unless framework responsibilities are affected.                                   |
| Startup, routes, layouts or configuration wiring                         | Expo app framework development, plus React owners for affected component composition, state or styles | Loading the framework body does not make every framework reference applicable.                                      |
| Isolated pure calculation with no component or framework contract change | The actual calculation, validation and testing responsibilities where applicable                      | Location in a React or Expo repository does not itself add component or framework duties.                           |

A pure function involved in a component's props, state or composition is not the isolated-calculation case. Its affected responsibilities still determine selection.
