# Testing

This project's verification commands: what each `mise` task checks, which of
them CI runs, and how to select the checks for a change. [Development Setup](../operations/development-setup.md) installs
the pinned tools these commands use, and
[Documentation validation](./documentation.md#checking-a-documentation-change) covers the checks for a documentation change.

## Check Commands

Run the narrower tasks for the surface a change touches; the `mise run check`
row says which task CI runs.

Run from the repository root.

| Command                             | What it does                                                                                                                                                                                                                                                                                                                                                   |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mise install`                      | Install the pinned tools                                                                                                                                                                                                                                                                                                                                       |
| `mise run format`                   | Rewrite Markdown, JSON, YAML, and TypeScript files with Prettier, and Rust files with rustfmt                                                                                                                                                                                                                                                                  |
| `mise run format:check`             | Fail when Prettier or rustfmt would change a file                                                                                                                                                                                                                                                                                                              |
| `mise run lint`                     | Run every linter below                                                                                                                                                                                                                                                                                                                                         |
| `mise run lint:markdown`            | markdownlint-cli2 over the Markdown files                                                                                                                                                                                                                                                                                                                      |
| `mise run lint:shell`               | shellcheck over `*.sh` files, `.agents/setup`, and `.agents/install-rust`                                                                                                                                                                                                                                                                                      |
| `mise run lint:docker`              | hadolint over Dockerfiles; passes when there are none                                                                                                                                                                                                                                                                                                          |
| `mise run lint:actions`             | actionlint over `.github/workflows/`                                                                                                                                                                                                                                                                                                                           |
| `mise run lint:powershell`          | PSScriptAnalyzer over `*.ps1`, `*.psm1`, and `*.psd1` files, flagging syntax Windows PowerShell 5.1 rejects, after checking that its settings still flag PowerShell 7-only syntax; passes when there are none                                                                                                                                                  |
| `mise run check:links`              | Resolve relative links in `docs/`, `images/`, `hosts/`, `.claude/agents/`, and the root Markdown files                                                                                                                                                                                                                                                         |
| `mise run check:docs`               | Validate the full OKF documentation bundle, metadata, navigation, links and local fragments                                                                                                                                                                                                                                                                    |
| `mise run check:amp`                | Run the Amp quality-hooks plugin's smoke test (`node --test`, no install needed)                                                                                                                                                                                                                                                                               |
| `mise run check:claude`             | Exercise the registered Claude SessionStart reminder and bootstrap in disposable checkouts with isolated provisioning inputs                                                                                                                                                                                                                                   |
| `mise run check:skills`             | Check that `skills-lock.json` and `.claude/skills/` list the same skills                                                                                                                                                                                                                                                                                       |
| `mise run lint:rust`                | clippy over the CLI, all targets, warnings as errors                                                                                                                                                                                                                                                                                                           |
| `mise run test:set-release-version` | Run the version write script, `.github/scripts/set-release-version.sh`, against temporary copies of the CLI's and the app's `Cargo.toml` and `Cargo.lock`: a release and a prerelease version, invalid versions, a missing placeholder or package, a duplicate entry, and CRLF files                                                                           |
| `mise run test:verify-release`      | Run the retained app release gate, `.github/scripts/verify-release.sh`, against temporary release files: the plan phase's output, the exact files, a missing, extra, or misnamed executable or installer, a directory in place of a file, a checksum mismatch, and an unset or unknown phase. Active CLI asset globs are checked by `test:cli-recovery`.       |
| `mise run test:assemble-release`    | Run `.github/scripts/assemble-release.sh`, which writes `SHA256SUMS` for the release's app executable and MSI, against temporary directories: the two lines in their fixed order, and a refusal for another file set, a changed file, or a hash that is not a SHA-256. It needs GNU `sha256sum` and GNU `find -printf`, so it runs on Linux (CI), not on macOS |
| `mise run check:release-shape`      | Check the temporary seven-stage CLI release and retained unsigned app builds, including the Mac app job and its measured signing tools; only inline sign-macos reaches the release Environment. The recovery source and signed-output boundary are checked against Security's active release record; this catches mistakes, not hostile edits.                 |
| `mise run test:release-shape`       | Run that check against the unchanged workflows, then against copies altered one change at a time, and expect each alteration to fail                                                                                                                                                                                                                           |
| `mise run test:installer-version`   | Run `.github/scripts/installer-version.sh`: a release `X.Y.Z` is kept, `0.0.0-dryrun.<n>` maps to `0.0.0`, and a version beyond the MSI limits or in another prerelease form is refused                                                                                                                                                                        |
| `mise run test:fetch-wix`           | Run `.github/scripts/fetch-wix.sh` with a stand-in `curl` and `dotnet`: a package whose SHA-256 differs from the pin is refused before `dotnet` runs, and a package with the pinned hash is installed from a NuGet.Config that lists only its folder                                                                                                           |
| `mise run test:rust`                | Run the CLI's unit and integration tests, which read the shared fixtures                                                                                                                                                                                                                                                                                       |
| `mise run deny:rust`                | `cargo deny` bans, licenses, and sources over the CLI's crates; the advisory check runs in its own workflow                                                                                                                                                                                                                                                    |
| `mise run lint:app`                 | clippy over the app's platform-independent crates (the mode dispatch, the view, the session, the icon, and the update feed), all targets, warnings as errors; the Tauri crate needs the web view and is linted by the Windows and macOS app CI jobs                                                                                                            |
| `mise run test:app`                 | Run the tests of those five app crates                                                                                                                                                                                                                                                                                                                         |
| `mise run test:app-frontend`        | Run the main window page's tests with Node: the order it draws views in, that it clears a typed token, and what a settings checkbox does                                                                                                                                                                                                                       |
| `mise run deny:app`                 | `cargo deny` bans, licenses, and sources over the crates the app's executable links, for the Windows and macOS targets; the advisory check runs in its own workflow                                                                                                                                                                                            |
| `mise run prepare:app-render`       | Install the locked, test-only browser controller and the checksum-verified Chromium the rendering gate uses, under this working copy; installs no OS package                                                                                                                                                                                                   |
| `mise run test:app-render`          | Render the main window's recorded configuration-editor states in the pinned Chromium and check layout, contrast, focus and the accessibility tree; needs `prepare:app-render` first                                                                                                                                                                            |
| `mise run check:notices`            | Fail when the checked-in licence notices in `app/notices/` no longer match `app/Cargo.lock`; `mise run notices:app` writes them again                                                                                                                                                                                                                          |
| `mise run check:app-pins`           | Fail unless the CLI's and the app's toolchain files name one channel and `app/tauri-cli.version` holds one exact version; `mise run test:tauri-cli-version` tests the script that reads it                                                                                                                                                                     |
| `mise run check:app-lock`           | Fail when the app's lockfile resolves a crate `marshal-cli` builds with, for Windows, macOS or Linux, to another version than the CLI's                                                                                                                                                                                                                        |
| `mise run check`                    | Run every gate above except the writing `format` and the rendering gate; this is what the Check job's `Run Checks` step runs                                                                                                                                                                                                                                   |

The Linux x64 rendering gate needs one explicit preparation step,
`mise run prepare:app-render`;
[Development Setup](../operations/development-setup.md#rendering-gate) says what
it installs and needs. `mise run test:app-render` runs the browser gate alone.
`mise run check` does not include it, so a checkout without the browser, and any
host other than Linux x64, can still run `check`. The Check job prepares the gate
and runs it as its own step after `mise run check`;
The [merge workflow](../../.github/workflows/merge-checks.yaml) lists the remaining steps. [App](../marshal/configuration.md#the-configuration-editor) describes the
checks and their limits.

The temporary recovery adds these checks to `mise run check`, without replacing
the normal app release-tool or installer checks:

| Command                                     | What it does                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mise run test:cli-recovery`                | Refuse wrong historical inputs, non-version mutations, wrong product/version and invalid release sets; exercise the actual workflow's version and signed-output assembly checks. Reuse the pinned historical version, assembler, publication-gate, installer-version and WiX-fetch suites in disposable inputs. |
| `mise run test:sign-macos`                  | Run the actual inline signing scripts with recording stand-ins: credential masking, certificate/team/expiry refusals, system-tool calls, notarization and cleanup. No real signature or credential is used.                                                                                                     |
| `mise run test:signed-pkg-refusals`         | Exercise both accepted designated-requirement forms and refusals for invalid signature, payload, receipt, team, notarization or checksum, plus cleanup, with stand-ins.                                                                                                                                         |
| `mise run test:cli-recovery-install-blocks` | Extract the recovery document's CLI check/migration/uninstall/bare-rollback blocks and run against stand-ins under bash and PowerShell. Registry-only cases remain hosted Windows checks.                                                                                                                       |

The Mac app's signing steps, staged in `.github/staged/release-macos-app.yaml`
until M2's pull request 3 wires them into the release, add these checks to
`mise run check`, apart from the recovery route's `test:sign-macos`:

| Command                           | What it does                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mise run test:staged-sign-macos` | Run the staged `sign-macos` scripts with recording stand-ins: each refusal, the flags and their order, `hdiutil create`'s three attempts, the notarization status read, the clean-up after a pass and after a failure at each step, and that no secret is printed. It also checks that no workflow names the staged file, that its `hdiutil create` arguments equal the app job's, and that the app job measures every tool the staged scripts call |
| `mise run test:staged-signed-dmg` | Run the staged `verify-macos` script, `test-signed-dmg.sh`, against stand-ins and produce each refusal: a disk image or app that is unsigned, ad hoc, misnamed, another team's or not stapled, a changed volume, link or `Info.plist`, a notary log of another submission, and a designated requirement that is not the default one                                                                                                                 |

Merge checks also run `cli-recovery-build.yaml` at a dry-run version on hosted
Windows/macOS, then `CLI Recovery Install Blocks` runs the recovery procedures
against those unsigned real CLI installers. It covers zsh/system bash and Windows
PowerShell5.1/7, including a standard local user install on hosted Windows. The
current app dry run and app install-block job remain separate. No hosted check,
unsigned artifact or stand-in satisfies F0's maintainer-owned native evidence.

The installed copies under `.claude/skills/` are generated and are excluded from
formatting and linting. [Agent Skills](../agent-work/skill-installation.md) owns
refreshing them and the upstream comparison that `check:skills` does not do.
